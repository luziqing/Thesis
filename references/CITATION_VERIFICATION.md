# 引用真实性核验协议

> 方法提炼自 [HKUSTDial/Supervisor-Skills](https://github.com/HKUSTDial/Supervisor-Skills) `paper-writer/references/verification-ladder.md` 与 `deep-research/references/citation-protocol.md`（CC BY-NC-SA 4.0 / CC BY-NC-SA-4.0），已适配中文学位论文（Markdown + Pandoc，`[@key]`）。
> 被 `survey` 与 `review` 模块共用。本项目已有 `scripts/verify_bib.py` / `scripts/online_bib_verify.py` 负责**格式与在线条目**校验；本协议负责**独立真实性核验与分级处置**，二者互补，不互相替代。

## 1. 为什么必须独立核验

在同一上下文里自检引用几乎无效：写出「Smith 等 (2021) 提出 X」的模型，被要求复核时会查同一份记忆并确认自己。生成与审查共享同一个错误。
引用幻觉（编造文献、错置作者/年份、把元数据当全文引用）又是最可被机械证伪的一类：文献要么检索得到，要么检索不到。因此把这一层外包给**独立的检索步骤**，而不是依赖模型对自己诚实。

## 2. 能力阶梯（纪律不降级，只降级核验机制，且须在交付说明中披露）

- **第 1 级 · 全新上下文核验器（首选）**：环境能派生子代理时，派一个干净上下文的子代理，输入只有正文（带引用标记）与文献表，不给它起草推理过程。它用本会话检索能力逐条核验。
- **第 2 级 · 同上下文接地**：无子代理但有检索（学术检索工具、网页检索、或 Crossref/Semantic Scholar/arXiv/DBLP 等公开 API）。每条文献从**实际检索响应**重新推导，绝不凭记忆；逐条比对声明。弱于第 1 级，须说明。
- **第 3 级 · 闭卷**：完全无检索。此时：只引用申请人提供的文献；每条只按引用级（元数据）引用；不新增任何文献；交付说明中明确「未做独立核验」。

中文期刊/学位论文等 API 覆盖差的文献，网页检索视为比索引元数据弱一级，最多算第 3 级，重要处要说明。

## 3. 何时触发独立核验

| 情形 | 独立核验 |
|---|---|
| 整篇论文 / 多节草稿 / 终稿模式 | **强制**，与引用数量无关 |
| 其余情况累计引用 ≥ 3 条 | **强制** |
| 其余情况单段或短节、引用 ≤ 2 条 | 可跳过，用行内清单即可 |
| 无引用 | 不触发 |

阈值取 3 是因为绪论与的相关工作几乎立刻超过；只有真正轻量的片段落到行内。本节表格与任何技能自身文字冲突时，以本表为准。

## 4. 核验器对每条引用做什么

**第 1 步：存在性与元数据。** 至少三种检索式：完整题目；作者 + 关键词 + 年份；核心关键词单独。比对题目、作者、年份、载体。

区分「检索不到」与「无法检索」：只有三种检索式都正常响应且零命中才算「检索不到」。工具报错、超时、限流、系统性空响应 = 检索本身失败 → 判定 INCONCLUSIVE，绝不判 NOT_FOUND。一次基础设施抖动不能删掉一条真实文献。

**第 2 步：引用点处的引用强度。** 正文写「某作者研究了 Y」= 引用级，元数据匹配即可。正文写「在基准 B 上达到 92%」或描述其流程 = 全文级，元数据无法支撑；除非申请人提供了全文或摘要，否则判定 OVERCLAIM。

## 5. 状态分级与处置

| 状态 | 含义 | 处置 |
|---|---|---|
| **VERIFIED** | 找到；元数据匹配；按引用级引用 | 保留 |
| **METADATA_MISMATCH** | 文献存在但作者/年份/载体不符 | 按检索结果改正；若检索源彼此矛盾或违背常识（如经典论文标成未来年份），挂起交申请人裁决 |
| **NOT_FOUND** | 正常检索、三种检索式零命中 | 删除该引用及它所支撑的句子，或通过检索找到真实替代；绝不作为事实保留 |
| **OVERCLAIM** | 文献真实但正文声称超出可用证据级别 | 把句子降写到引用级（「X 等研究了 Y」） |
| **INCONCLUSIVE** | 工具错误、超时、限流、系统性空响应 | 不通过也不删除；重试，持续失败则挂起并在交付说明中交申请人 |

挂起项在**交付说明**（正文之外的说明区）列出。任何状态都不允许用往正文里插方括号标记的方式解决——正文禁止出现这类脚手架标记（调研报告例外，见下）。

## 6. 诚实边界

本核验能抓住：编造文献（NOT_FOUND 是核心值）、元数据错置、把元数据当全文引用（OVERCLAIM）。
抓不到：真实存在但论断本身错误的引用（需全文，属证据匹配检查）；非引用的编造（机构细节、数字——属写作期证据纪律）。
元数据改正与 OVERCLAIM 判断仍含模型判断，检索后端本身也可能出错；METADATA_MISMATCH 的挂起 safeguard 正是为此。这一层加固的是引用层，不是全局保证。

## 7. 收敛规则

只有**没有未解决项**才可交付。这不等于「全部 VERIFIED」：一条项在 VERIFIED / 已改正 / 已删除 / 已降写到引用级 / 明确挂起交申请人之后即为已解决。未解决的 NOT_FOUND / METADATA_MISMATCH / OVERCLAIM 退回写作环节做定点修复（只改受影响的句子，不重写），然后重新核验。

## 8. 与调研报告的差别（重要）

`survey` 产出的**调研报告**是面向申请人的工作文档，允许统一的「未确认标记」，例如「[未确认：该方向未检索到相关工作]」，这是诚实信号。
**论文正文**（绪论、相关工作、结论）禁止任何方括号标记；两套约定服务于不同产品，不要把调研报告约定带进正文。
中文调研报告中技术术语保留英文，前后各留一个半角空格。

## 9. 行内清单（轻量片段 / 无独立核验时）

- [ ] 每个 `[@key]` 都能追溯到申请人材料或本会话检索结果？
- [ ] 无凭记忆生成的文献？
- [ ] 无对被引用工作的方法编造（把综述写成「元分析」等）？
- [ ] 用到来源处都有文内引用标记，而非只有文末文献表？
- [ ] 文献表与文内引用双向一一对应？
- [ ] 每条含作者、题目、载体、年份（无法确认的剔除；非必要字段可省）？
- [ ] 引用格式全文统一（本项目默认 GB/T 7714，`[@k1; @k2]` 合引）？
