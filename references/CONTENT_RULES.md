# Content Rules — 内容层规则（审阅 / 改写模块共用）

> **来源**：`gulucaptain/Best-Paper-Writing-Skill` v1.2（本地副本 `D:\WritingSkills\Best-Paper-Writing-Skill`）。其规律来自 2021–2025 年 60 篇 CVPR / ICCV / NeurIPS 获奖论文的逐句标注与统计：55 篇拟合、5 篇（2024）留出测试；配图排版规则来自其中 44 篇的配图统计。推文档案见 `D:\WritingSkills\_tweet_2124679935302480122\tweet.md`。
> **定位**：本文件是**判断线索**，不是新的唯一真源。事实保真、hedging、术语、`[@key]` / `$...$`、交付格式一律以 SKILL.md 的 **Chinese Writing Boundaries** 为唯一真源；冲突时以该节为准。
> **载体边界**：本 skill 面向中文 Markdown + Pandoc 学位论文。下列规则已剔除英文会议论文、LaTeX 模板与双栏排版专属项（§7）。

## 1. 主张—证据映射（claim map）

写或审之前先列一张内部表（可进 `review`/`report` 交付，不写进论文正文）：

| 主张 | 证据（表 / 图 / 引用 / 数字） | 证据支持的最强措辞 | 级别 |
|---|---|---|---|
| 例：方法在 3 个数据集上优于最强基线 | 表 3-2，MAE 降低 2–6% | 「在 3 个数据集上优于 X」 | 头条 |
| 例：模块 A 提供主要增益 | 消融表 3-5 | 「移除 A 后 MAE 上升 4.1%」 | 支撑 |

- **一个主张只出现一次**：绪论、贡献列表、摘要、结论表述同一主张时不重复堆砌；重复即合并，不是各写一遍。
- **强度对齐**：动词阶梯 `证明/证实 > 表明/验证 > 提示/可能` 只按证据强度选，禁止上调（与 CW Boundaries 禁改清单一致）。
- **头条数字 1–2 个**支撑核心主张，其余数字归表；「表格报数、正文讲主张」。
- **无证据的主张**：软化措辞或标 `【待补证】`（本 skill 统一占位符，不用来源仓库的 `[TODO]` / `\TODO{}`），不得新增数字、基线、数据集或引用。
- **摘要 / 绪论 / 贡献**三处同一主张的强度必须一致；发现不一致按 `MAJOR/P1` 报。

## 2. 绪论漏斗：具体前人 → 缺口（条件 + 原因）→ 洞察 → 方法 → 结果

- 先**具体肯定前人**（点名工作与它成立的条件），不要「近年来…引起广泛关注」式泛背景；泛背景最多两句。
- 缺口写清**什么条件下失效、为什么失效**，而不是一句「现有方法存在局限」。
- 「洞察」是对**问题本身**的观察，方法由它推出；不是架构描述，也不是「本文针对上述局限提出…」的空转句。
- 最相近工作要点名，并给**一条可核查的差异**（机制 / 适用范围 / 代价 / 假设 / 输入 / 输出 / 评价指标）。
- 结论：张力由方法解决，方法之后给结果。中文学位论文的「研究意义」「不足与展望」按学校模板与 CW Boundaries 保留，**不套用英文顶会「缺陷不进摘要/绪论」的偏好**。

## 3. 方法章：需要 → 机制 → 性质，组件按关系展开

- 每个组件按 `需要（上一环节留下什么问题）→ 机制（谁比较 / 谁移动 / 如何计算）→ 性质（为何成立、代价）` 写。
- 组件之间写**关系**：「A 单独使用会让误差跨步骤累积，因此 B …」，不写 `A 做 …。B 做 …。C 做 …。` 的并列清单。
- 机制缺失时**如实留空并追问**，不用「状态 / 记录 / 检查 / 协议」这类听着完整但没信息量的抽象名词填空。
- 术语一旦引入即固定，不轮换同义词（与 `consistency` 模块一致）。

## 4. 实验章：消融与主张一一对应

把 §1 的表扩展为 `主张 → 方法小节 → 实验（表/图）→ 消融`：

- 每个主主张至少有一处实验或图表承载；每处消融对应一个明确主张，不做无归属的「堆实验」。
- 没有证据支撑的主张，在绪论里软化或标 `【待补证】`，不靠形容词补。
- 分析段落先给结论再引证数字，并解释**原因 / 机制**（归因），不复述表格流水账（与 `EXPERIMENT.md` 的 B3 一致）。
- 讨论章把结果放回文献语境：与最相近工作比较一致或差异之处（与 `EXPERIMENT.md` 的 B4 一致）。

## 5. 图表：先规划后画

写方法 / 实验章前先出**图表规划表**（交付给作者，不写进正文）：

| 图/表号 | 承载哪个主张 | 位置 | 类型 | 所需素材 | 状态 | 题注首句（结论） |
|---|---|---|---|---|---|---|
| 图 3-1 | 方法总体流程 | 3.1 节前 | 示意 | 用户已述机制 | 可画 | 三段式结构将 X 与 Y 解耦 |
| 表 3-2 | 头条结果 | 3.3 节 | 数据表 | 待补实验数值 | 留白 | 在 3 个数据集上优于最强基线 |

- 一张图只承载一个主张；每个主主张有图或表承载。
- 题注首句写**结论 / takeaway**，不是「图所示为…」；参见 `CAPTION_GUIDE.md`（其 LaTeX `\bicaption` 示例仅适用于 `.tex` 项目）。
- 机制示意图只画用户已述内容；**结果图 / 曲线 / 数值一律留白**，不得编造图像、渲染、曲线或数字（与 CW Boundaries「不编造」一致）。
- 全篇配色、命名、符号与正文一致（与 `consistency` 模块联动）。
- **不套用** CVPR 双栏「Figure 1 放第 1 页通栏」及其 8 类路由；学位论文图表位置服从学校模板与章节逻辑。

## 6. 反 AI 腔：统计口径只作线索

来源仓库的统计（英文语料）可作**偏离提示**，不是硬阈值，更不追求把稿子改成「统计平均值」：

- 句尾分词短语（`, making …`，英文获奖论文 ~8%、AI 草稿 30%+）→ 中文对应检查「句尾挂意义复述」；命中先判是否真的空转，有信息则保留。
- 连接词密度、句长、短句连发、句首「关键洞察是…」套式、`first / SOTA on all benchmarks` 式无范围宣称 → 作为 `deai` / `review` 的**线索**，命中 ≠ 改写判据（CW Boundaries 已明确）。
- 每项规则都有上下限，不是向均值靠拢；**宁可保留一句有记忆点的枢轴句，也不要为过检查器把句子磨平**。
- 推文式文案模板（`· 机制 / · 结果`、`谁该用：`、`判断：`、星数社会证明）是**营销文案**，只用于归档说明与对照记录，**严禁写入论文正文**；学位论文不用钩子、口号、社会证明。

## 7. 不可迁移清单（明确禁止）

| 来源规则 | 不迁移原因 |
|---|---|
| CVPR author kit / LaTeX 模板、TikZ 资产、`check_figures.py` 的 `main.tex` 口径 | 本 skill 是 Markdown + Pandoc；`[@key]` / `$...$` 才是保护对象 |
| 英文「no dashes」「20–24 words」「we / our voice」「no trailing participial clause」原样阈值 | 中文标点、句长、人称语域不同；CW Boundaries 与 `ACADEMIC_STYLE_ZH.md` 为准 |
| 「局限 / 失败案例不进摘要与绪论」 | 中文学位论文按学校模板常含研究意义与不足说明，且禁改清单保护绪论研究意义句 |
| Figure 1 八类路由、第 1 页通栏、两栏排版统计 | 会议双栏版式专属 |
| 8 类论文路由 L1–L8、venue fit、rebuttal、投稿门控 | 英文会议专属；`review` 只面向中文送审/答辩（见 Do Not Use） |
| `intake_form.html` 填表、`report.md`、留出盲评集 | 来源仓库工作流组件，本 skill 不新增脚本 / 表单 / 评测资产 |
| 获奖论文范例句（`exemplars/`） | 英文短句版权归原作者，且会引入英文笔法；不得复制进中文论文 |

## 8. 交付前内容层检查清单

1. 每个实证主张有证据，措辞强度 ≤ 证据强度；无证据处标 `【待补证】`。
2. 核心主张只出现一次；摘要 / 绪论 / 贡献 / 结论强度一致。
3. 缺口含「条件 + 原因」，洞察是对问题的观察；最相近工作有可核查差异。
4. 组件写关系而非并列；机制缺失处如实留白。
5. 消融与主张一一对应；分析段是归因不是复述数字。
6. 图表先有规划表；结果图留白，题注首句是结论。
7. 数字、单位、p 值、`[@key]`、`$...$` 逐字一致（CW Boundaries Quick Checks ①）。
8. 未把英文顶会规则、推文营销模板写进正文。

> 检查不通过时按 `<!-- MODULE (L##) [Severity] [Priority]: ... -->` 报问题项；**审阅模块只报不改**，改写类模块仍走 CW Boundaries 的 `审计 → CHECKPOINT → 改写 → 报告` 四步。
