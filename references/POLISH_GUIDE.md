# 忠于原意的语言润色指南

> 方法提炼自 [HKUSTDial/Supervisor-Skills](https://github.com/HKUSTDial/Supervisor-Skills) `paper-polish`（CC BY-NC-SA-4.0），已改写为中文学位论文语境。
> 🔴 **唯一真源**：任何改写动作先读 `SKILL.md §Chinese Writing Boundaries`（优先级 / 禁改清单 / 证据纪律 / 反模式黑名单 / Quick Checks / CHECKPOINT）。本指南与之冲突时**以本节真源为准**；`scripts/deai_check.py` 只产出线索，命中 ≠ 改写判据。
> 与 `deai` 模块分工：`deai` = 诊断并削减 AI 痕迹；`polish` = 通用语言润色（语法、流畅、语气校准、按节惯例、学术表达）。二者共用同一套禁改清单与证据纪律。

## 0. 压倒一切的规则：忠于作者原意

润色是「帮作者把想说的说得更好」，不是「换成润色者想说的」。作者最怕的是编辑悄悄改变了文本的主张。

**绝不静默做出改变科学含义的修改**：
- 不加强或削弱结论（`提示`→`证明`、`可能与……相关`→`导致`），除非告知作者并请其确认；
- 不把相关写成因果；
- 不悄悄丢掉限定语（「在该数据集上」），让有界结论看起来普适；
- 不因为某段啰嗦就删除或大幅压缩作者的一个论点——建议删，但不要删了再称之为润色。

判据很简单：**纯语言修改**（语法、语序、同义 smoother）可自由做；**可能触及含义**的修改要么不做，要么做并显式标出请作者确认。拿不准归哪类时，按第二类处理。
自检：改完把版本与原稿并排，逐句问「这句的科学含义还是作者原来那句吗？」每个「不完全是」都必须标出。

## 1. 禁止编造内容

润色是把已写的东西说得更好，不是补全内容。原文没有的，一律不加：
- 数据、数字、阈值、参数；
- 公式（原文没有就不「帮忙」加一个）；
- 实验结果或比较；
- 引用；
- 方法名、框架名、机理解释。人文/定性片段尤其易损：原文只描述现象，不要给它套上「话语分析」「与前人不同」这类作者没写的东西。

若某段确实缺证据或论证，**不要编**——留一句给作者的括注，如「（建议在此补充支撑该论断的数据）」「（这一步是我的推断，原文未陈述，请确认）」。判断与填补都留给作者。

## 2. 默认保守

不是每位作者都要大改。默认轻触：**小改优于大改，不改优于小改**。作者已 hedge 的表述（`可能`、`一定程度上`）不要「优化」回更强论断。
若认为需要句子级以上的结构重写，停下来说明，让作者在「轻润色 / 深度重写」间选择；不要默认走深度。

## 3. 一次润色的流程

1. **先理解**：动笔前弄清这段在说什么、在论文里扮演什么角色（绪论定位？结果陈述？）。读不懂就问，不猜着改。
2. **找真问题**：是表层语法措辞，还是逻辑本身断了（一段塞多点、论断无论据、相关写成因果）？结构性问题句子润色救不了——如实告诉作者需要重写该节，并转 `paper-writer`/人工重写。
3. **修改**：在忠于原意前提下让语言更清晰地道。分节惯例、语气校准、AI 腔见下。
4. **交代改动**：先给干净的润色稿，再简要说明主要改动，尤其标出可能触及含义的项。

## 4. 按节惯例（不同章节不同语域，不一套语气用到底）

| 章节 | 必须回答 | 推荐顺序 | 常见毛病 |
|---|---|---|---|
| 绪论 | 为何重要？已知什么？缺什么/争什么？本文问什么、怎么做？ | 立重要性 → 述已知 → 点空白/争论 → 陈述目标 → 指价值/路径 | 教科书式开场；空白只暗示不明说；从「已知」跳到「本文做」漏掉「为何仍需」；提前泄露方法/结果细节 |
| 方法 | 同行能否据此（加一条明确引用的规程）复现？ | 设计/样本 → 材料/数据源 → 步骤 → 测量 → 分析统计 → 伦理声明 | 「按常规条件」「用标准方法」「数据经统计分析」「差异显著（无检验、无效应量）」等空话 |
| 结果 | 观察到什么、在什么条件下、定量支撑？ | 指向图表 → 主观察 → 定量细节 → 预期/意外模式 → 必要处才比前人 | 在结果段做解释（那是讨论的活）；把该进正文的结果塞附录；「高于对照」无效应量或检验 |
| 讨论 | 主发现意味着什么？与前人关系？哪些解释成立？哪些局限约束解读？ | 重述主发现 → 合理释义 → 比前人 → 点局限 →  implication → 必要处指未来 | 换个说法重复结果；把相关当机制 |
| 结论 | 核心贡献是什么？哪个发现是决定性的？意义与边界？ | 回到目标 → 决定性发现 → 贡献/意义 → 边界/展望 | 缩略版讨论；引入新实验；用空泛赞美收尾 |
| 摘要 | 什么空白？做了什么？发现了什么？为何值得关心？ | 背景 → 具体空白 → 方法 → 关键结果（有数字则给） → 含义 | 细节不分主次；夸大（与正文同标准处理） |
| 标题 | 哪几个词让它可检索、准确、有趣、不过度断言？ | 见 `references/TITLE_OPTIMIZATION.md` | 「关于……的研究」空开场、模糊钩子、未核实的「首个」、术语堆叠 |

**中文学位论文特别**：绪论的研究意义句、结论章的功能性总结受真源保护，按语境判定，不批量删除；被动语态在施动者无关时保留；`本文/本研究` 不改成 `我/我们`。

## 5. 语气校准：不让作者过度断言

可信度来自分寸。**只调语言强度，绝不发明证据去支撑强结论**。

匹配动词与证据强度（与真源「动词阶梯：证明/证实 > 表明/验证 > 提示/可能，只允许下调、禁止上调」一致）：

| 强度 | 中文 | English |
|---|---|---|
| 强（扎实设计与数据） | 表明、证实、确立、揭示 | show, demonstrate, establish, reveal, identify |
| 中（合理但未确定） | 提示、说明、支持……的看法、与……一致、指向 | suggest, indicate, be consistent with, point to |
| 弱（超出直接观察/推测） | 可能反映、或源于、似乎、看来、或可解释为 | may reflect, could arise from, appears to |
| 描述证据本身 | 有限/稀少/不足；不断积累/初现；稳健/可靠/可观 | limited/scant/insufficient; emerging/accumulating; robust/convincing |

对跑在证据前面的词（`首次`、`唯一`、`最优`、`卓越`、`颠覆性`、`碾压`、`遥遥领先`、`proves`、`unprecedented`、`state-of-the-art`）→ 软化或标出请作者确认；带数字/p 值的 `显著` 有证据，不删（真源豁免）。

## 6. 公平对待前人

不要把前人研究削成稻草人来烘托本文。别写「以往方法全都失败」，写精确差异：「尽管已有研究显示了 X，但它们在 Y 条件下的表现仍不清楚。」既守诚信，也把空白讲清楚。

## 7. 去 AI 腔

扫描典型信号并改写，清单见 `references/DEAI_GUIDE.md` 与 `references/modules/DEAI.md`。命中≠必删，先问该词是否承载信息。
中文常见：套话开场、宏大框架、「不仅……而且……更……」三项凑数、加粗开头列表、破折号堆砌、同义轮换（把同一对象叫三个名字）。
一条警告：把所有信号剥掉后，文字可能干净但死气沉沉。解药仍是不编事实——变化句长、用确切事实而非形容词承载分量、直说真实的取舍与局限。

## 8. 中译英改写（用于英文摘要 / 投稿衍生论文）

源文是中文或中英混杂时，不逐句翻译：
- **先提含义，再写句子**：重述每句核心命题，再用地道英文学术句写出，不跟中文语序；
- **补回隐含逻辑**：中文常把对比、因果、递进、让步隐含在语序里，英文要明示；
- **术语稳定**：术语、数据集名、模型名、统计术语选定一种译法并保持一致，不模糊改写；
- **修中式英语残留**：删冗余类别词、把主题突出式开头改成主谓句、修冠词/单复数/时态、把堆叠名词化拆回动词；
- **翻译时不拔高**：谨慎的中文稿不授权更强的英文稿，校准仍按证据。

## 9. 文件 vs 粘贴文本；长文档

- 草稿在工作区文件里 → 直接改文件，用版本 diff 作为精确改动记录，再给作者一份只列「含义风险项」的简短说明。
- 文本粘贴在对话里 → 回复中给完整润色稿 + 改动说明。
- 长文档：不能只精修前几页后面划水。必须分块时标注「第 i 部分，共 N 部分」，每块都是完整可用产物；跳过部分不得声称已全文润色。

## 10. 无法读取的内容

源文某部分不可读（Word 导出里嵌成图片的公式、损坏的表格、读不清的图）→ 不猜内容、不写看似合理的文字。明确告诉作者不可读元素在哪，需要其人工核对。

## 11. 何时「这不是润色能解决的」

1. **超出句子修复**：逻辑链断裂、讨论与核心想法无关 → 内容问题，说明并建议先重写该节再回来润色。
2. **核心论断可能不成立**：自报数据显示方法被简单基线追平/超过 → 不为其写防御、不编乐观解读；直说，并建议先用 `topic`（选题层面）或 `review`（稿件层面）做核查再润色。

诚实指出问题比把它润色掉更有帮助。

## 12. 交付格式

核心永远是**作者可立即使用的干净润色稿**：
1. 先给润色后正文（流畅行文，不逐行加注）；
2. 后给主要改动 3–5 条，明确说明是否有改动可能触及科学含义、需要确认，以及哪里建议补数据/论证而没有编造；
3. 含义风险项用并排 before/after 清单：原句 / 改句 / 理由 / 风险，让作者一眼裁决；
4. 三块交付固定为：`检查结果` / `改写稿` / `改动说明（含未改及原因）`。

说明要轻——它支撑正文，不喧宾夺主。
