# 学位论文选题评估指南

> 方法提炼自 [HKUSTDial/Supervisor-Skills](https://github.com/HKUSTDial/Supervisor-Skills) `idea-evaluator`（CC BY-NC-SA 4.0），已改写为中文学位论文语境。
> 适用：选题论证、开题报告前置评估、判断某一研究方向是否值得投入一整个学位周期、在两三个候选选题间做结构化取舍。
> 不适用：已经做完并开始写论文（此时用 `logic`/`experiment`/`review`）；纯粹从零头脑风暴；对已有稿件做审稿。

## 0. 评估姿态

以「资深导师 + 盲审专家」双视角评估。目标是**在投入数月之前否掉弱选题**，并把「有潜力但未成形」的选题打磨到可开题的形态。
全程遵守证据纪律：任何打分都要引用申请人自述的证据；查不到就标「未核实，需文献核查」，不编造。

## 1. 第一印象与选题定位

用一句话说清：这个选题是 **新问题（Novel Problem）/ 新方法（Novel Method）/ 新场景（New Setting）/ 新解释（对已有现象的机理新解）** 中的哪一类？
能否用一句话写出「故事主线」？写不出来 → 请申请人重述，暂不评估。

范式按**方法**判定，不按院系名称：
- 实验/仿真/消融/模型/算法 → 理工科范式（走五维 + 致命缺陷）
- 文本分析/档案/概念论证 → 人文范式
- 问卷/访谈/统计/田野 → 实证社科范式

若范式不清，只问一句：「核心方法是实验、调查、文本分析，还是理论推导？」
非理工科范式的替代五维与致命缺陷见 `idea-evaluator/references/domain-evaluation-frameworks.md`（原始资料）；本项目默认对象为理工科/地球物理/AI for Science 学位论文。

## 2. 致命缺陷审计（前置闸门，先于打分）

最多列 **2 条**。每条写明缺陷、检测规则、具体防御方案。10 条标准缺陷（已适配学位论文）：

| # | 缺陷 | 检测提问 | 红旗信号 |
| --- | --- | --- | --- |
| F1 | 相对最近工作无新意 | 相对最接近的一篇已发表工作，本选题多出什么？ | 说不出一句话贡献；或「用了更大模型」「组合两个现成方法」 |
| F2 | 选题与学位类型/载体错配 | 这是博士选题还是硕士选题？工作量撑得起吗？ | 硕士体量包装成博士、或博士选题只够一篇课程论文 |
| F3 | 对标点不是真正的基线 | 该问题上最近三年最强公开结果是什么？ | 基线超过 12 个月未更新；领域已有更强方法却未列入 |
| F4 | 动机不成立 | 若这个问题明天被解决，谁受益、受益多少？ | 回答只有「做这个窄问题的人」，说不出外部受益方 |
| F5 | 能力与选题不匹配 | 有效每周工时、技能深度、理论/应用偏好与选题匹配吗？ | 两个以上不匹配标记同时出现（见 §3） |
| F6 | 不可验证的论断 | 哪个实验若出特定结果就能证明主论点？该实验在范围内吗？ | 说不出该实验，或实验超出范围（如声称跨领域却无跨领域实验） |
| F7 | 伦理或数据获取阻断 | 所需数据现在都能拿到吗？涉及人/伦理审查是否已获批？ | 任一必需资源缺失且学制内拿不到 |
| F8 | 范围过大 | 开题报告里列了几条贡献？ | 超过 4 条，或横跨「基准 + 方法 + 理论 + 系统」多种类型 |
| F9 | 拿方法找问题 | 是先遇到真实问题，还是先想用某个技术？ | 说不出一个 motivating 的真实失败案例 |
| F10 | 未考虑失效边界 | 该方法在什么条件下失效？局限章怎么写？ | 说不出两种失效模式；把方法当万灵药 |

**严重度**：
- CRITICAL：学制/现有资源内无法防御，或同时出现 2 条以上 MAJOR → 短路，直接裁决「建议更换选题」，跳过 §3–§6。
- MAJOR：需 2–4 周专门工作才能防御。
- MINOR：一周内的写作或文献工作可解决。

**数据证伪核心机制 = 自动 CRITICAL**：若申请人自报数据或附件已显示核心机制被基线/消融/简单对照追平或超过，直接锁定「建议更换选题」，不写防御、不编造乐观阈值。区分「已被数据证伪」与「尚未验证」——后者不套用本规则。

**新颖性 (F1) 的检索接地**：环境具备检索能力时，从选题抽取 2–3 组关键词（核心方法 + 领域、机制 + 任务、技术 + 基准），检索并列出 3–5 篇最接近的已发表工作（题目、作者、年份），逐篇说明差异轴：被作用对象 / 机制 / 输入粒度 / 问题设定。相似题目本身不构成重复；只有四个轴都找不到差异才算重复。检索结果只支持「谁在何时做了什么」的元数据判断，不引用摘要里的数字与方法细节。检索不到 ≠ 证明新颖，报告为「在这些关键词下未检索到直接重叠工作」。无检索能力 → 新颖性标注「未核实，需文献核查」。

## 3. 学制周期与能力匹配

把选题归入六类：应用研究 / 基础理论 / 交叉学科 / 前沿探索 / 数据密集 / 技术创新。
对照申请人自述：每周有效工时、技能深度、理论与应用的强弱。输出不匹配标记：

| 维度 | 记录 | 判定 |
|---|---|---|
| 选题类别 | … | … |
| 预期周期（月） | … | 与学制剩余时长比对 |
| 每周有效工时 | … | 与实验/推导工作量比对 |
| 匹配度 | 绿 / 黄 / 红 | 红 = 建议缩范围或换类型 |

周期短于可现实执行窗口 → 不匹配标记。防御策略：缩范围、合作、改类别、或换题。

## 4. 五维打分

每维 1–10 分，从 5 分起，向上移动必须有证据。两类证据都算：
1. 申请人报告的实测结果（引用原话）；
2. 站得住脚的机制论证（标注「基于机制，尚未数据确认」）——扎实但未验证的机制可以打到 8–9 分，但必须点名一个验证实验；不要系统性压低未验证选题。
既无数据也无机制 → 停在 5 分，标「无依据」。

| 维度 | 含义 | 学位论文判据示例 |
|---|---|---|
| 更高 Higher | 效果/精度提升 | 相对最强基线的定量增益 |
| 更快 Faster | 效率/成本降低 | 训练/反演/计算耗时下降 |
| 更强 Stronger | 鲁棒性、抗噪、泛化 | 跨区块/跨数据集稳定性 |
| 更省 Cheaper | 数据/标注/算力成本降低 | 少样本、弱监督、低成本采集 |
| 更广 Broader | 跨域迁移或统一 | 地球物理方法迁移到相近反演问题 |

归属纪律：若亮眼增益可能来自外围因素（路由、后处理、更强底座、有利样本），在该维度封顶，直到有消融隔离核心机制。

## 5. 范式转换探测（4 问）

1. 是否挑战了领域默认接受的隐含假设？
2. 是否处理了「房间里的大象」——人人都看见但没人愿碰的问题？
3. 是否乘上技术周期变化（如大模型使此前不可行的方法变得可行）？
4. 若该问题自行消失，领域是否会发生实质改变？（Hamming 规则）

两个以上「是」= 有颠覆潜力，标注并建议深化。

## 6. 可行性检查

对照申请人自述资源，逐项标等级 + 缓解方案：
- **算力风险**：实验能否在可用硬件上跑完（注意单模型一次加载的硬约束）？
- **数据风险**：数据是否可获取，是否需要昂贵标注或私有来源？
- **工程风险**：实现是否匹配技能栈？
- **时间线风险**：编码 + 实验 + 写作 + 修改的端到端时长是否落在选题周期内？

## 7. 完整性门控（静默执行，不输出逐条结果）

- [inspection] 每个维度分数引用了申请人自述的具体证据，无「凭感觉」打分。
- [inspection] 可行性判断引用自述资源，非通用假设。
- [inspection] 新颖性判断要么引用具体文献，要么标「未核实」。
- [inspection] 致命缺陷具体可操作，无「这可能行不通」这类空话。
- [inspection] 裁决与打分一致：强通过要求至少两维 8+ 且无 CRITICAL。
- [inspection] 范式转换声明点明是哪一问回答为「是」。
- [attestation] 生命周期预测基于领域近期节奏推理，申请人应结合本子领域常识复核。

任一 [inspection] 失败 → 降级裁决并把对应小节标「需申请人关注」。
