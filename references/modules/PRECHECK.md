# Precheck Module Reference — 盲审前自查

Purpose: 在论文提交盲审/答辩前进行全面的自查检查，覆盖态度印象、题目、摘要、目录、绪论、方法、结果图表、讨论、结论、文献综述、参考文献等维度。

本模块源自博士学位论文盲审前自查的实战经验，侧重于外审专家一眼即可识别的常见问题。盲审如同开盲盒，唯有反复自查才能降低风险。

---

## P0: 总则 — 态度·工作量·创新性

盲审是一场"30分钟快速筛选"。专家通过论文的表面工程判断学术严谨性，再通过工作量确认毕业资格，最后以创新性衡量学术上限。三者缺一不可。

### P0-A: 态度 — 决定生死的第一印象

| 检查项 | 严重度 | 说明 |
|--------|--------|------|
| 格式统一性：字体、字号、行距、段间距全篇是否一致 | Critical/P0 | 格式混乱直接暴露态度问题 |
| 错别字、标点、术语拼写 | Critical/P0 | 封面、摘要、目录中的错字属一票否决红线 |
| 图片清晰度与美观度 | Major/P1 | 模糊图片令专家质疑实验过程的严谨性 |
| 参考文献格式规范 | Major/P1 | 文献格式错误是态度不认真的直接体现 |
| 章节逻辑连贯性 | Critical/P0 | 堆砌痕迹明显、章节缺乏内在联系属硬伤 |
| 技术路线图是否清晰 | Major/P1 | 缺失技术路线图使专家难以把握研究全貌 |

**核心原则**：先把表面功夫做到位。严格按照学校模板排版，花时间美化图表，确保格式规范、逻辑清晰。内容可以迭代精进，但低级错误不可原谅。

### P0-B: 工作量 — 证明投入的基础门槛

| 检查项 | 严重度 | 说明 |
|--------|--------|------|
| 主体干货章节数量：博士 ≥ 5 章，硕士 ≥ 3 章 | Major/P1 | 脚本：章节计数 |
| 总字数：博士 ≥ 7 万字，硕士 ≥ 3 万字 | Major/P1 | 脚本：字符计数 |
| 绪论文献综述是否充分展开 | Minor/P2 | 可适当扩展以增强工作量 |
| 结果分析与讨论是否详细展开 | Major/P1 | 避免浅尝辄止 |

**核心原则**：专家信奉"没有功劳也有苦劳"。工作量充足时，即使创新性一般，专家也会给予一定宽容。字数不足时可在绪论、结果讨论部分深入展开，必要时添加附录。

### P0-C: 创新性 — 决定上限的灵魂

| 检查项 | 严重度 | 说明 |
|--------|--------|------|
| 创新点数量：博士 ≥ 3 个，硕士 ≥ 1 个 | Major/P1 | LLM 判断 |
| 摘要中是否明确点出创新点 | Critical/P0 | 不提创新点等于默认没有 |
| 结论中是否再次强调创新贡献 | Major/P1 | 关键位置必须旗帜鲜明 |
| 创新点表述是否具体可感知 | Major/P1 | 避免"具有重要意义"等空泛表述 |

**核心原则**：即使研究是"老问题 + 老方法"，也要从物理机制新解释、工程参数新优化等角度提炼新意。创新点不能藏着掖着，必须在摘要和结论中直接亮明。

## P1: 题目自查

题目是论文的脸面，好题目须简明且确切。

| 检查项 | 严重度 | 检测方式 |
|--------|--------|----------|
| 封面题目与正文首页题目是否一致 | Critical/P0 | 脚本：提取 cover 与正文标题对比 |
| 专业术语、人名、地名、缩写有无错别字 | Critical/P0 | 脚本 + 人工 |
| 外审专家能否一眼理解研究核心 | Major/P1 | LLM 判断 |
| 题目长度是否在 15–30 字之间 | Minor/P2 | 脚本：字符计数 |
| 中英文题目语义是否对齐 | Major/P1 | LLM 判断 |
| 是否聚焦于一个核心主题 | Major/P1 | LLM 判断 |

**实战要点**：

- 题目出现任何错别字都会严重损害论文严谨性的第一印象。封面与内文题目必须完全一致。
- 忌冗长罗嗦：不要把博士期间所有支线任务都塞进标题，一个题目对应一个核心主题。
- 忌模糊笼统：评委一看题目就应大概知道核心工作和贡献。研究若只涉及某一具体分支，可用"主标题 + 副标题"增强信息清晰度。
- 不要超出盲审专家的预期：一个对你的领域只有基本了解的人，看到题目时能否猜到论文在解决什么问题？超出太多预期意味着风险。

## P2: 摘要自查

摘要是论文的电梯演讲，须在几分钟内传递全部重要价值。

| 检查项 | 严重度 | 检测方式 |
|--------|--------|----------|
| 结构完整性：背景意义 + 研究内容 + 方法 + 结论/创新点 | Major/P1 | 脚本：关键词覆盖检测 |
| 字数是否在 500–1000 字范围 | Minor/P2 | 脚本：字符计数 |
| 结果描述是否使用了定量数据而非模糊表述 | Major/P1 | 脚本：检测模糊词 |
| 关键词数量 3–5 个 | Minor/P2 | 脚本：关键词行解析 |
| 中英文摘要内容是否一致 | Major/P1 | LLM 判断 |
| 是否包含明确的核心结论 | Critical/P0 | LLM 判断 |
| 是否突出了创新亮点 | Major/P1 | LLM 判断 |

**模糊词黑名单**（出现在摘要中应标记为 Major/P1）：

```
很大程度上|取得了较好效果|有所改善|得到了提高|效果显著|明显优于|具有重要意义|有着重要价值
```

**推荐替换**：使用具体数值，如"精度提高了15%""耗时减少了30%"。

**实战要点**：

- 结论缺失是重灾区。很多摘要只罗列做了什么，却对"因此我们得到什么重要论断"含糊其辞甚至根本不提。
- 通篇"分析了""探讨了""研究了"缺乏亮点。把最创新、最硬核的发现用最直白的语言展现出来。
- 推荐句式："基于……背景，旨在……，通过……方法，发现……，表明……"。简洁有力，要素齐全。
- 英文摘要是国际化学术规范的基本体现，也直接反映严谨程度，须认真对待。

## P3: 目录自查

目录是论文逻辑的缩影，也是专家快速评判研究设计的窗口。

| 检查项 | 严重度 | 检测方式 |
|--------|--------|----------|
| 标题层级是否存在跳跃（如 1.1 直接到 1.3） | Critical/P0 | 脚本：编号连续性检测 |
| 各级标题格式是否统一（加粗、字号、字体） | Major/P1 | 脚本 + 人工 |
| 页码与正文实际位置是否一致 | Critical/P0 | 人工检查（PDF导出后核对） |
| 目录是否完整包含所有章节 | Major/P1 | 脚本：与正文标题对比 |
| 章节之间是否呈现递进或并列的逻辑关系 | Major/P1 | LLM 判断 |
| 小标题是否具体有指向性 | Major/P1 | LLM 判断 |
| 标题是否精炼且具概括力 | Minor/P2 | LLM 判断 |

**目录结构八原则**：

1. **主线贯穿**：好的目录应有一条清晰的视角或主线将各部分串联，增强整体连贯性。围绕核心问题聚焦，提炼具体维度，避免"大而全、浅而散"。
2. **标题具体化**：小标题须避免抽象表述，聚焦可操作的具体维度。体现主题词、研究对象和预设方向，细节越丰富越能展示研究工作量。定小标题需要大量资料支撑，不是拍脑袋的产物。
3. **案例驱动**：采用"解剖麻雀"式的研究策略，通过深入剖析具体案例揭示普遍规律。思路不清时应回归具体文本重新梳理。
4. **逻辑衔接**：章节之间须建立清晰的逻辑关系，避免内容松散。呈现从个体到社会、从现实到哲思、从特殊到普遍的有序结构。
5. **言简意赅**：标题须精炼且具概括力，避免冗长的解释性标题。辅助性说明保留在个人笔记中，正式呈现时只保留高度凝练的条目。
6. **概念清晰**：内容呈现须清晰明确。含糊往往源于概念界定不清晰，每个词的使用都需仔细斟酌。
7. **结论先行**：小标题是研究设计和思维层次的直接反映。一个具体的小标题，背后是一段已经想清楚、有明确边界和内容的论述。
8. **反复迭代**：好的目录是改出来的。修改的本质是思维的迭代和认知的升级，每一次修改都是对研究问题、方法和意义的再审视。

## P4: 绪论自查

绪论不是文献综述的简单堆叠，而是一条逻辑链：**为什么要做 → 大家做到哪了 → 还有什么问题 → 我如何解决**。其作用是讲一个逻辑清晰的故事，把读者从广阔背景一步步引到具体研究问题上。

| 检查项 | 严重度 | 检测方式 |
|--------|--------|----------|
| 是否包含研究背景 | Major/P1 | 脚本：关键词扫描 |
| 是否包含研究现状概述 | Major/P1 | 脚本：关键词扫描 |
| 是否明确指出现有问题/研究空白 | Critical/P0 | 脚本：gap 关键词检测 |
| 是否给出解决方案和技术路径 | Major/P1 | 脚本：关键词扫描 |
| 是否有论文组织结构说明 | Minor/P2 | 脚本：检测"本文结构""章节安排"等 |
| 文献是否按学术脉络组织而非简单罗列 | Major/P1 | LLM 判断 |

**实战要点**：

- 不要只是罗列"张三（2020）研究了……李四（2021）研究了……"。要用文献讲出学术发展的脉络、当前的争论焦点，以及尚未解决的空白。
- 逻辑结构应像漏斗：背景 → 脉络 → 争论 → 空白 → 你的切入点。层层递进，最后聚焦到研究的针尖上。
- 所有引用的图表、数据、核心观点必须规范注明出处。

---

## P5: 方法自查（材料与方法）

方法部分的目标是确保可重复性。严谨的研究必须让同行能根据描述复现实验或分析过程。

| 检查项 | 严重度 | 检测方式 |
|--------|--------|----------|
| 实验设备型号、软件版本等是否交代清楚 | Major/P1 | LLM 判断 |
| 方法步骤是否有理有据（而非"拍脑袋"） | Major/P1 | LLM 判断 |
| 算法参数、采样频率等关键参数是否完整列出 | Major/P1 | LLM 判断 |
| 方法描述是否支持可复现性 | Critical/P0 | LLM 判断 |
| 模型假设是否明确声明 | Major/P1 | 脚本：检测"假设""假定""设定"等 |
| 非独创方法是否引用了原始文献 | Major/P1 | 脚本：引文检测 |
| 方法与前言提出的问题是否严丝合缝 | Major/P1 | LLM 判断 |

**可复现性关键要素检测**（脚本辅助）：

```
设备|型号|版本|频率|参数|配置|环境|平台|分辨率|采样|纯度|浓度
```

方法章节若未包含上述关键词中的至少3个 → Minor/P2 提示。

**实战要点**：

- 逻辑自洽是核心：前言里提出的问题和假设，对应需要什么实验或方法来验证？方法部分必须与研究目的严丝合缝。
- 尊重他人成果：如果不是独创方法，必须引用原始文献，这是基本学术规范。

---

## P6: 结果与图表自查

结果是论文的血肉。摆数据不是目的，有逻辑地呈现证据才是关键。

| 检查项 | 严重度 | 检测方式 |
|--------|--------|----------|
| 图表标题是否**自明**（不看正文也能理解） | Major/P1 | LLM 判断 |
| 横纵坐标单位、字体、颜色、线宽全篇是否统一 | Major/P1 | 人工检查 |
| 图片分辨率是否满足印刷要求（≥300 DPI） | Major/P1 | 脚本：图片元数据检测（可选） |
| 是否存在纯数据堆砌而不分析的段落 | Major/P1 | 脚本：复用 experiment 模块 B3 |
| 表题在表上方、图题在图下方 | Minor/P2 | 脚本：Markdown 结构检测 |
| 每个图表是否在正文中被明确引用 | Major/P1 | 脚本：交叉引用检测 |
| 统计学信息是否完整（P值、置信区间、样本量） | Major/P1 | LLM 判断 |

**图表自明性要素**：标题中应包含实验对象、变量名称和比较维度，使读者不依赖正文便能理解图表含义。

**实战要点**：

- 图文并茂，但要以文释图。不能只有图而没有文字描述。对每个重要图表，用文字清晰说明展示了什么趋势、比较了什么差异、说明了什么问题。文中提到的每一个结果都须明确指出"见图X/表Y"。
- 结果呈现要像讲故事一样有层次，先说什么后说什么须有章法。结果是用来回答前言中提出的问题的，要保持呼应。
- 结果部分只做客观描述，不要开始解释和评论——那是讨论部分的职责。

---

## P7: 讨论自查

讨论是体现学术功力的灵魂部分。

| 检查项 | 严重度 | 检测方式 |
|--------|--------|----------|
| 是否回答了"为什么会出现这样的结果" | Major/P1 | 脚本：归因关键词检测（复用 B3） |
| 是否与前人研究进行了对比分析 | Major/P1 | 脚本：引文回溯检测（复用 B4） |
| 对不一致结果是否给出了合理解释 | Major/P1 | LLM 判断 |
| 是否存在单纯复述结果数据的段落 | Major/P1 | 脚本：归因密度检测 |
| 是否承认了研究局限性 | Major/P1 | 脚本：检测"局限""不足""限制"等 |
| 是否提出了未来研究方向 | Minor/P2 | 脚本：检测"未来""进一步""展望"等 |

**实战要点**：

- 开篇旗帜鲜明地亮出核心发现，直接回应前言中的假说：结果支持了它，还是推翻了它，还是部分支持？为什么？
- 切忌把结果部分的内容换种说法再重复一遍。要分析结果的深层含义、可能的原因、内在机制。与已有研究对比，结果一致还是冲突？冲突的可能原因是什么？
- 引用文献是为"我"服务，即"六经注我"。讨论中引用文献是为了支撑或对比你的分析，不是为了展示阅读量。每一篇被引文献都应在论证逻辑中扮演特定角色。
- 坦诚说明研究的局限性，并提出未来可进一步研究的方向。这体现客观、严谨与格局。
- 讨论最忌"散"。围绕几个核心结论展开，层层深入。

---

## P8: 结论自查

结论是给那些可能只看这一部分的人准备的总结。

| 检查项 | 严重度 | 检测方式 |
|--------|--------|----------|
| 结论是否明确、条理清晰 | Major/P1 | LLM 判断 |
| 是否不同于摘要的简单重复 | Major/P1 | LLM：摘要-结论相似度检测 |
| 是否包含核心发现总结 | Minor/P2 | 脚本：复用 B5 发现关键词 |
| 是否包含研究启示/意义 | Minor/P2 | 脚本：复用 B5 启示关键词 |
| 是否包含局限性/未来工作 | Major/P1 | 脚本：复用 B5 局限关键词 |
| 即使不看全文，只看结论能否把握核心贡献 | Major/P1 | LLM 判断 |

**实战要点**：

- 浓缩精华、掷地有声：用高度概括的语言重申最重要的发现和论断，回答"这个研究到底说明了什么"这个终极问题。
- 避免简单重复：不要抄摘要，也不要只是各章小结的集合。要更精炼、更有力度，甚至可以上升到更一般的意义层面。
- 可独立成段：即使不看全文，只看结论部分也能清晰把握论文的核心贡献。

---

## P9: 文献综述自查

文献综述要展示驾驭和整合文献的能力。

| 检查项 | 严重度 | 检测方式 |
|--------|--------|----------|
| 是否围绕核心问题展开，而非泛泛堆砌 | Major/P1 | LLM 判断 |
| 是否按主题分类而非按作者/年份罗列 | Major/P1 | 脚本：复用 A1 检测 |
| 每组文献后是否有评述性总结 | Major/P1 | LLM 判断（复用 A2） |
| 最后是否推导出研究空白 | Critical/P0 | 脚本：复用 A3 检测 |
| 范围是否聚焦于核心问题 | Major/P1 | LLM 判断 |

**实战要点**：

- 有脉络、有评述：不是简单罗列"A说了……B说了……"，而是按时间发展、学术流派、理论脉络组织，讲清楚领域如何一步步发展到今天，关键争论点在哪里。
- 综述结尾必须收网：明确点出当前研究的空白或不足，而你的研究正是要填补这一空白。这是与前人研究的接驳点。
- 范围要聚焦，围绕核心问题展开，不要扯太远。

---

## P10: 参考文献自查

参考文献是细节，但细节决定成败，直接反映学术习惯和严谨程度。

| 检查项 | 严重度 | 检测方式 |
|--------|--------|----------|
| 文内引用与文献列表是否一一对应 | Critical/P0 | 脚本：双向交叉校验 |
| 引用格式是否全文统一 | Major/P1 | 脚本：复用 bibliography 模块 |
| 文献排序是否符合规范 | Minor/P2 | 脚本：编号或字母序检测 |
| 特殊条目（专利、网页、标准等）格式是否正确 | Minor/P2 | 脚本：类型识别 + 格式校验 |
| 作者名、期刊名、页码等信息是否准确 | Major/P1 | 人工 + 脚本辅助 |

**铁律**：文内引的每条参考文献列表里不能少，列表里有的文内不能多。

**实战要点**：

- 格式统一：全文引用格式（作者、年份、期刊名、卷期页码、字体、标点）必须完全一致。善用文献管理软件，但提交前务必手动检查，尤其是特殊条目。
- 信息准确：作者名、期刊名、书名、页码，一个字母、一个数字都不能错。这既是对原作者的尊重，也是对自己负责。

## 使用方式

```bash
# 完整盲审前自查（所有检查项）
uv run python $SKILL_DIR/scripts/precheck.py thesis_dir/

# 仅检查特定维度
uv run python $SKILL_DIR/scripts/precheck.py thesis.md --checks title,abstract,toc

# 输出为 JSON 格式
uv run python $SKILL_DIR/scripts/precheck.py thesis_dir/ --json
```

## 自查优先级

按照盲审专家的注意力顺序排列：

1. 态度与第一印象（格式、错别字、图表质量）
2. 题目与封面（核心研究的脸面）
3. 摘要（全文门面与电梯演讲）
4. 目录（逻辑缩影与研究设计窗口）
5. 参考文献（学术规范的直接体现）
6. 图表质量（视觉专业度）
7. 绪论逻辑链
8. 方法可复现性
9. 讨论深度
10. 结论完整性
11. 文献综述聚焦度
12. 工作量与创新性
