# Topic Module Reference — 选题与开题评估

Purpose: 评估学位论文选题是否值得投入一个完整学位周期，或在多个候选选题间做结构化取舍。

> 🔴 **边界**：本模块做「开题前的选题论证」，不是「从零写论文」，也不替代 `logic`/`experiment`（那些针对已写稿件）。评估中的任何打分必须引用申请人自述证据；无证据标「未核实」。

## 核心流程（8 步）

1. **第一印象 + 范式定位**：一句话主线；判定 新问题/新方法/新场景/新解释；按**方法**（非院系）判范式。
2. **致命缺陷审计（前置闸门）**：最多 2 条，先于打分。10 条标准缺陷 F1–F10（无新意 / 层次错配 / 对标点错 / 动机空 / 能力不匹配 / 论断不可验证 / 数据伦理阻断 / 范围过大 / 方法找问题 / 无失效边界）。
   - 短路规则：任一 CRITICAL → 直接裁决「建议更换选题」，跳过 3–6。
   - 数据已证伪核心机制 → 自动 CRITICAL，不写防御、不编阈值。
   - F1 新颖性在可检索时须接地：列 3–5 篇最接近工作 + 差异轴；检索不到 ≠ 新颖。
3. **学制周期与能力匹配**：六类选题 × 每周有效工时/技能深度 → 绿/黄/红。
4. **五维打分**（1–10，从 5 起）：更高 / 更快 / 更强 / 更省 / 更广。实测结果或标注的机制论证都可加分；无依据停 5 分；外围因素带来的增益须封顶待消融。
5. **范式转换探测 4 问**：隐含假设 / 房间里的大象 / 技术周期 / Hamming 规则；≥2 个「是」= 有颠覆潜力。
6. **可行性**：算力 / 数据 / 工程 / 时间线，逐项标等级 + 缓解。
7. **完整性门控**：静默执行；[inspection] 失败 → 降级裁决。
8. **裁决**：`建议开题` / `修改后开题` / `建议更换选题` + 最先要做的三件事。机制型高分附「待验证实验」。

## Quick Start

```
输入：选题描述 + （可选）每周有效工时/技能自述/学制剩余时长 + （可选）候选选题列表
输出：references/TOPIC_EVALUATION.md §8 的 7 节结构
```
